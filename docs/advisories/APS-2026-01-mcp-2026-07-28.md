# APS-2026-01 — MCP specification 2026-07-28

- **Status:** Informative advisory, issued with Standard v3.3.1 (2026-09-27). The normative treatment is Definition of Done item 26 in Standard v4.0.
- **Affects:** Part II · Layer 2 (tool integration — MCP by default), Part II · Layer 8 (Security & Identity), DoD 14, anti-pattern 15, and the `tool-design-mcp` skill.
- **Primary sources:** [the 2026-07-28 specification](https://modelcontextprotocol.io/specification/2026-07-28) and [its changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog); the [release post](https://blog.modelcontextprotocol.io/posts/2026-07-28/) (28 Jul 2026).

## Why this advisory exists

Standard v3.3 tells you to target MCP **2025-11-25** and to "branch for the 2026-07-28 release candidate." That release candidate was locked on 21 May 2026 and published as final on **28 July 2026**. The four Tier-1 SDKs (TypeScript, Python, Go, C#) supported it on release day, and Rust supported it in beta. The Layer 8 controls in v3.3 are still correct. They were written for the 2025 transport and auth model, though, and several of their assumptions changed. This note says which ones, and what to do before v4.0 makes it normative.

## What changed that the standard cares about

| Change (spec reference) | What it means for a v3.3 product |
|---|---|
| **Stateless core.** Protocol-level sessions and the `Mcp-Session-Id` header are removed (SEP-2567); `initialize` is removed, and the protocol version and capabilities travel in each request's `_meta` (SEP-2575). Servers that need state across calls mint explicit handles. | State kept in the transport session is now state nobody can see. Move it into explicit, server-minted handles or your own store. This is DoD 2 (*state externalized*) applied to the protocol. |
| **Multi round-trip requests** replace server-initiated requests such as `elicitation/create`, `sampling/createMessage` and `roots/list` (SEP-2322). The server returns `input_required`; the client retries with the answers and echoes an opaque `requestState`. | Human-in-the-loop through elicitation now arrives as an `input_required` result, which fits the durable-pause pattern (Part II · Layer 5). The spec says servers **MUST** treat `requestState` as attacker-controlled input, and **MUST** integrity-protect it (e.g. HMAC or AEAD) when it influences authorization, resource access, or business logic. |
| **Routing headers.** `Mcp-Method` is sent on every request, and `Mcp-Name` on `tools/call`, `resources/read` and `prompts/get`, so that gateways can route and inspect traffic without parsing the body. Servers **MUST** reject a header that disagrees with the body (SEP-2243). | A gateway can now authorize per tool at the edge, which gives Layer 8 an enforcement point outside the model. Gateways that route on these headers **SHOULD** reject requests from older protocol versions, which do not check the headers against the body. |
| **Caching hints.** List and read results carry `ttlMs` and `cacheScope` (`public` or `private`); a `private` result **MUST NOT** be served to a different user (SEP-2549). | Re-verify the tool-definition hash pin (DoD 14) on every refetch, not only at install. Treat `private` as a tenant boundary in any shared cache. The same leak path applies to tenant isolation. |
| **Authorization hardening.** Dynamic Client Registration is deprecated in favour of **Client ID Metadata Documents**. Clients **MUST** validate a present `iss` against the recorded issuer before redeeming a code (RFC 9207, SEP-2468). Persisted credentials **MUST** be keyed by issuer and never reused with another authorization server. An **enterprise-managed authorization** extension exists (SEP-990). The server **MUST NOT** pass through the token it received from the client, as before. | Anti-pattern 15 grows a variant: a client that can only register through DCR. New clients register with a Client ID Metadata Document. Validate `iss`. Bind stored credentials to their issuer. |
| **Deprecations.** Roots, Sampling and Logging are deprecated (SEP-2577). Tasks move to the `io.modelcontextprotocol/tasks` extension and MCP Apps to `io.modelcontextprotocol/ui` (SEP-2663). The legacy HTTP+SSE transport is formally deprecated. Deprecated features get a minimum 12-month window, so the earliest removal is in a revision dated on or after **28 Jul 2027**. The window can shrink to 90 days for an active security risk (SEP-2596). | Take no new dependencies on deprecated features. Put a sunset date on existing ones. |
| **Official conformance suite:** [`modelcontextprotocol/conformance`](https://github.com/modelcontextprotocol/conformance). | Run it in CI against your server and your client. As of this advisory, the `latest` npm tag (0.1.16) predates 2026-07-28 support, so pin the pre-release that provides `--requirements 2026-07-28` (0.2.0-alpha.11 when this was written). |

## What to do now

- [ ] Inventory every MCP connection: which side you own (client or server), the protocol revision it speaks, and a sunset date for anything still on 2025-11-25.
- [ ] Remove any dependence on `Mcp-Session-Id`. Carry cross-call state as explicit handles or in your own store.
- [ ] Treat `requestState` as untrusted input, and integrity-protect it where it influences authorization or business logic.
- [ ] Re-verify pinned tool-definition hashes whenever a cached `tools/list` expires. Never let a `private` cache entry cross a user or tenant.
- [ ] New clients register with a Client ID Metadata Document, validate `iss`, and key stored credentials by issuer. Token passthrough stays forbidden.
- [ ] Build no new features on Roots, Sampling, or Logging.
- [ ] Add the official conformance suite to CI at a pinned version.
- [ ] If an MCP gateway fronts your servers, authorize on `Mcp-Method` and `Mcp-Name`, reject mismatches, and reject protocol versions that predate the headers.

v4.0 turns this checklist into DoD item 26 (*MCP protocol & auth baseline*).
