# Minimum Artifact Set

## 1. Purpose

AITM-SMB is artifact-driven, but not document-driven.

The method requires semantic completeness, not paperwork volume.

---

## 2. Minimum Compact Set

A Compact application MAY combine several contracts into fewer documents, but must preserve:

```text
1. Transformation Intent
2. Capability + Current State
3. Capability Diagnosis
4. Intervention Map
5. Target State
6. Initiative / Roadmap
7. Governance & Authority
8. Scorecard / Evidence
9. Decision & Assumption Log
```

---

## 3. Standard Set

A Standard application SHOULD include:

```text
Transformation Intent
Business System Map
Capability Map
Capability Diagnosis
Capability Network
System Constraint
Intervention Map
Prioritization Matrix
Target Operating Architecture
Decision Rights Map
Transition States
Transformation Roadmap
Pilot Plan
Governance Canvas
Observability Plan
Adoption Plan
Transformation Scorecard
Value Realization Report
Decision & Assumption Log
```

---

## 4. Artifact merging

Artifacts MAY be merged when:

```text
scope is small
traceability remains intact
ownership remains clear
agent parsing remains reliable
```

Example:

```text
Capability Map + Capability Diagnosis
```

MAY exist as one file if stable IDs and sections remain distinct.

---

## 5. Artifact splitting

Artifacts MAY be split when:

```text
scope is large
multiple owners exist
independent lifecycle exists
agent context size requires it
```

---

## 6. Rule

Do not create documents to satisfy a checklist.

Create artifacts to preserve:

```text
decision quality
traceability
evidence
ownership
execution
```
