# Phase 5 — Target Operating Architecture

## Objective

Design the future operating system across multiple Capabilities, not only isolated solutions.

## Required inputs

- approved Outcomes;
- Capability Map;
- Capability Network;
- Capability Diagnosis;
- selected Interventions;
- AI Suitability / Autonomy Assessments where relevant;
- constraints.

## Method

Use:

1. `design/TARGET_STATE_DESIGN.md`
2. `design/CAPABILITY_NETWORK.md`
3. `design/SYSTEM_TRANSFORMATION_MODEL.md`
4. `design/TARGET_OPERATING_ARCHITECTURE.md`
5. `design/DECISION_RIGHTS_ARCHITECTURE.md`
6. `design/INFORMATION_KNOWLEDGE_ARCHITECTURE.md`
7. `design/APPLICATION_BOUNDARIES.md`
8. `design/LOCAL_OPTIMIZATION_GUARD.md`

## Activities

1. create Target States for selected Capabilities;
2. map inter-capability dependencies;
3. identify the current system Constraint;
4. integrate Capability Target States into one Target Operating Architecture;
5. define roles and Decision Rights;
6. define information and knowledge ownership;
7. define application and integration boundaries;
8. define automation and AI responsibilities;
9. assess system effects and likely Constraint Migration;
10. define governance, metrics, and economic boundaries.

## Outputs

- Capability Target States;
- Capability Network;
- System Constraint;
- Decision Rights Map;
- Target Operating Architecture;
- System Effect Assessments;
- updated Decision & Assumption Log.

## Exit condition

The Target Operating Architecture is ready for roadmap design only when:

```text
target behavior is explicit
AND dependencies are understood
AND material authority is explicit
AND local optimization risks are considered
AND system-level metrics exist
```
