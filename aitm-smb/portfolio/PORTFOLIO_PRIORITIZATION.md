# Portfolio Prioritization

## 1. Purpose

Individual initiative attractiveness is not enough.

Portfolio selection considers interactions.

---

## 2. Portfolio-level criteria

Evaluate:

```text
Outcome leverage
Constraint leverage
Dependency leverage
Shared-enabler leverage
Learning value
Change saturation
Resource contention
Risk concentration
Economic exposure
```

---

## 3. Dominance rule

When two initiatives create similar value, prefer the one with:

```text
lower irreversibility
shorter evidence loop
fewer hard dependencies
lower change burden
greater shared-enabler value
```

---

## 4. Change saturation

The organization has limited capacity to absorb change.

Track:

```text
number of changing roles
number of changing workflows
number of changing decision rights
number of new systems
number of new AI behaviors
```

High transformation WIP increases hidden coordination cost.

---

## 5. Portfolio stop condition

Do not add another Initiative when:

```text
critical ownership is missing
current pilots have not produced evidence
change capacity is saturated
shared architecture is unstable
```
