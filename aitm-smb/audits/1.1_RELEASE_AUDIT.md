# AITM-SMB 1.1 Release Audit

**Result: PASS** · framework version `1.1.0` · 2026-09-28

This audit records how the 1.1.0 release was checked. Unlike the 1.0 audits, every mechanical check here can be rerun from this repository:

```text
python3 tools/validate.py
python3 tools/validate.py --engagement examples/compact-scenario-b
python3 tools/build_dist.py
```

Judgment checks follow [`MAINTENANCE.md`](../MAINTENANCE.md) §2 and [`skills/39-audit-framework-integrity/SKILL.md`](../skills/39-audit-framework-integrity/SKILL.md).

## 1. Method

1. **Pre-release review of the internal 1.0.0.** Nine reviewers each took one area: canonical core; agent protocol and registries; artifact contracts; skills 01–20; skills 21–39; diagnostics and phases 0–3; design and phases 4–6; execution, governance and phases 7–8; open-source readiness. A second reviewer then tried to refute every finding, and a completeness pass looked for cross-cutting gaps.
2. **Consolidation** against one written specification (gate identifiers, record contracts, identifier registry, producer map, profiles, lifecycle wiring). Each file had exactly one editor.
3. **Worked example.** A complete fictional Compact engagement ([`examples/compact-scenario-b/`](../examples/compact-scenario-b/)) was written against the contracts and checked by an independent reviewer. Writing it exposed contract ambiguities that reading alone had missed.
4. **Release review of the consolidated tree**: eight reviewers across five focuses:
   - a closure check of every 1.0.0 finding, split across three reviewers;
   - a no-dropped-rules comparison against the 1.0.0 files, split across two reviewers;
   - a consistency sweep;
   - an agent walk-through of a new engagement;
   - an accuracy check of the public documents.
5. **Final fixes** decided in one place and applied by the owner of each file, followed by a residual cross-file sweep.

## 5. Choices a maintainer may want to revisit

These were decided to make the release consistent. Each is recorded where it lives and can be changed in a later MINOR release.

- **License.** MIT, the same as the host repository. CC BY 4.0 was considered (ADR-0005).
- **AI authority classes for profile triggers:** low = L0–L2, moderate = L3, high = L4–L5 ([`APPLICATION_PROFILES.md`](../APPLICATION_PROFILES.md) §2).
- **Unknown answers at profile selection.** The base defaults to Standard and Measured is added. A Governed condition is treated as holding unless the Outcome owner records otherwise. An add-on declared without a base is read as Standard plus the add-on ([`PROFILE_SELECTION.md`](../PROFILE_SELECTION.md)).
- **The system-effect check runs before `HG-INITIATIVE`,** which is stricter than the 1.0.0 wording ("considered").
- **Gate G requires a confirmed value conclusion** (`VALUE_CONFIRMED`), which is stricter than 1.0.0 ("business effect evidenced").
