# AITM-SMB 1.1.0 Release Notes

**Consolidation & open-source release** · 2026-09-28 · MINOR (compatible with the 1.x Public Methodology API)

AITM-SMB 1.1.0 is the first public release. It keeps every stable object, identifier, profile, intervention family, autonomy level and agent status from 1.0.0 (see `PUBLIC_API.md`). It changes how the method is written down: each rule and record shape now has one owner, the lifecycle runs end to end through the skills, and the project ships what an open-source method needs: a license, a quickstart, a worked example, a validator, and release automation.

The change list is in `CHANGELOG.md`. This file explains why the release exists and how to move a 1.0.0 engagement to it.

## Why a consolidation release

Before publication, the internal 1.0.0 went through an independent review: nine parallel reviewers, one per area, each finding checked by a skeptic. The review confirmed 254 findings: 4 blockers, 79 major, 147 minor and 24 nits. Most were one of these three patterns:

1. **Restated definitions that had drifted apart.** The human decision gates, autonomy labels, intervention families, minimum valid path, value states, and roughly fifteen record shapes each appeared in two to five files, and the copies differed. The 1.0.0 audit reported "one canonical source per stable concept".
2. **Execution the lifecycle never reached.** No phase or orchestrator invoked pilot design, pilot evaluation, rollout, evaluation datasets, or authority promotion (skills 25, 27, 29, 32, 34). Phase 7 required a Rollout Plan that nothing produced.
3. **Claims the shipped tree did not support.** The docs described an automated integrity audit that was not included, and "Core and Full distributions" that were never defined. Active files still used the deprecated AI-first framing, for example `skills/04-map-ai-opportunities`.

`audits/1.1_RELEASE_AUDIT.md` summarizes how each class was closed.

## Highlights

- **Gates you can check.** Nine human decision gates with stable IDs (`STANDARD.md` §8). Each approval is a Decision naming the gate, its subjects, and the human who approved it. `tools/validate.py --engagement` fails when a record is marked approved without such a Decision.
- **One record contract per shape.** `CANONICAL_CONCEPTS.md` names where each record is defined. Modules own meaning, contracts own field names (ADR-0004).
- **A lifecycle that runs.** Pilots are designed in Phase 6; they are run, evaluated, promoted and rolled out in Phase 7, and measured in Phase 8. Every orchestrator names its specialists, and every skill declares the gates it stops at.
- **Usable by agents.** A root `SKILL.md` makes the folder one installable skill. Every numbered skill has a description, phase, gate flags and a fixed shape. The handoff block (`AGENT_OUTPUT_STANDARD.md`) is required at every handoff and carries `open_gates`.
- **Usable by people.** `QUICKSTART.md` walks through a first Compact engagement. `examples/compact-scenario-b/` is a complete fictional engagement that passes the trace validator. `docs/crosswalk-agentic-product-standard.md` shows where AITM-SMB hands off to engineering practice.

## Upgrading a 1.0.0 engagement

Nothing changes meaning. Only names and locations moved. To upgrade:

1. **Rename fields** using the table below. IDs stay the same.
2. **Record gate approvals as Decisions.** For each approval you already have, add a `DEC-###` with `gate: HG-…`, `subject_ids`, `approved_by` and `status: approved`.
3. **Add CURRENT States.** For each Capability, add a State record with `type: CURRENT` (`CORE_MODEL.md` §3), and point `current_state_id` at it.
4. **Move evidence into the Evidence Register.** EVD records and Evidence Debt go into an `evidence-register` instance (`artifacts/evidence-register.md`).
5. **Move the conformance declaration.** The declaration is now `conformance:` inside the Transformation Intent.
6. **Update skill paths** if your tooling uses them (`CHANGELOG.md` path table).
7. **Validate:** run `python3 tools/validate.py --engagement <your-workspace>`, fix what it reports, and use `MISSING:<reason>` for links that genuinely do not exist yet (`TRACEABILITY.md`).

## Compatibility promise

Unchanged from 1.0.0. Within 1.x, stable object meanings, stable identifiers, profiles, intervention families, autonomy levels and agent statuses are not redefined incompatibly (`PUBLIC_API.md` §9). Field names inside record contracts are not part of that promise; when a MINOR release renames one, the release notes include a migration table like the one above (`VERSIONING.md`).
