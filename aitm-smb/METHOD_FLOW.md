# AITM-SMB Canonical Method Flow

## 1. One-page method

AITM-SMB transforms an SMB through one traceable chain:

```text
1. Frame Outcome
2. Discover Capabilities
3. Map Current System
4. Diagnose Gaps & Causes
5. Design Interventions
6. Select & Prioritize
7. Design Target Operating Architecture
8. Design Transition
9. Pilot & Evaluate
10. Roll Out & Govern
11. Measure Value
12. Evolve
```

---

## 2. Canonical reasoning chain

```text
Outcome
→ Capability
→ Current State
→ Gap
→ Cause
→ Intervention
→ Initiative
→ Target State
→ Transition State
→ Pilot / Slice
→ Rollout
→ Operating Model
→ Metric
→ Evidence
→ Value
→ Evolution
```

---

## 3. Minimum valid path

A compact AITM-SMB application MUST still contain:

```text
Outcome
→ Capability
→ Gap
→ Intervention
→ Target State
→ Initiative
→ Metric
→ Evidence
```

No profile may skip these semantic layers.

---

## 4. Mandatory human gates

Human approval is required before:

```text
approving Outcomes
selecting material Initiatives
changing Decision Rights
increasing AI authority
accepting material risk
committing material budget
approving Target Operating Architecture
promoting from pilot to rollout
declaring value realized
```

---

## 5. Mandatory challenge questions

At every major step ask:

### Outcome
What business result must change?

### Capability
What must the organization become capable of doing?

### Gap
What prevents that capability today?

### Cause
What explains the gap?

### Intervention
What is the simplest effective change?

### AI
What specifically requires probabilistic intelligence?

### Autonomy
Why is human approval insufficient?

### System
What downstream/upstream effect will this change create?

### Transition
How can we test this safely and reversibly?

### Value
What evidence proves that the business improved?
