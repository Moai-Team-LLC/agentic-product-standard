# AITM-SMB Skill Registry — 1.0

## Skill classes

AITM-SMB skills are divided into four classes.

### A. Phase Orchestrators — 01–10

These coordinate specialist skills and artifacts.

They MUST NOT redefine methodology semantics.

```text
01 discover transformation
02 map current system
03 diagnose capabilities
04 design interventions
05 prioritize initiatives
06 design target architecture
07 build roadmap
08 design operating model
09 measure evolution
10 audit engagement
```

### B. Diagnostic Specialists — 11–16

```text
11 discover capabilities
12 separate symptoms / gaps / causes
13 assess AI suitability
14 assess autonomy
15 design capability target state
16 validate root cause
```

### C. System & Transformation Design — 17–24

```text
17 map capability network
18 identify system constraint
19 assess system effects
20 design target operating architecture
21 design transition states
22 build transformation portfolio
23 design decision rights
24 audit local optimization
```

### D. Execution & Governance — 25–35

```text
25 design pilot
26 design evaluation
27 build eval dataset
28 design observability
29 plan rollout
30 design adoption
31 operationalize governance
32 evaluate pilot
33 assess value realization
34 manage authority promotion
35 audit operational readiness
```

### E. Framework Operations — 36–39

```text
36 select application profile
37 build context bundle
38 audit conformance
39 audit framework integrity
```

## Orchestration rule

An orchestrator delegates bounded reasoning to specialist skills.

A specialist skill owns the detailed procedure for its concept.

If an orchestrator and specialist conflict, the specialist procedure plus the normative methodology source wins.


## Stability

Skill numbers `01–39` are stable identifiers for the 1.x line.

New 1.x skills SHOULD use new numbers rather than repurpose an existing skill number.
