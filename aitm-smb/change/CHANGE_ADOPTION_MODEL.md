# Change Adoption Model

## 1. Purpose

Transformation fails when the technical system changes but human behavior does not.

AITM-SMB treats adoption as architecture execution.

---

## 2. Adoption dimensions

```text
Role clarity
Skill readiness
Trust
Workflow fit
Incentives
Manager behavior
Exception handling
Feedback
Support
```

---

## 3. Adoption record

```yaml
adoption:
  capability_id:
  affected_roles: []
  behavior_changes: []
  skills_required: []
  training_required: []
  incentive_changes: []
  trust_risks: []
  support_model:
  feedback_channel:
  adoption_metrics: []
```

---

## 4. Adoption metrics

Examples:

```text
target workflow usage
override rate
manual bypass rate
time-to-competence
support requests
correction rate
exception handling quality
```

Adoption metrics do not substitute for business Outcome metrics.

---

## 5. Resistance as evidence

Resistance MAY indicate:

```text
poor communication
bad incentives
real workflow degradation
loss of control
unresolved risk
incorrect target-state design
```

Do not treat all resistance as a people problem.
