# Governance Operating Model

## 1. Purpose

AITM-SMB governance ensures the transformed operating system remains safe, effective, owned, and economically rational.

Records: AI controls per AI-enabled Capability in the AI Governance Canvas (`artifacts/ai-governance-canvas.md`); ownership and cadence in the Operating Model (`artifacts/operating-model.md`). Authority changes: `governance/AUTHORITY_ESCALATION_MODEL.md`. Changes to AI components: `governance/AI_CHANGE_CONTROL.md`.

---

## 2. Governance objects

Governance SHOULD cover:

```text
Outcome
Capability
Decision Rights
AI Authority
Data Access
Knowledge Ownership
Model / Provider
Tool Access
Evaluation
Incident Handling
Cost
Change
```

---

## 3. Governance roles

A small SMB MAY combine roles, but responsibilities should remain explicit.

Common responsibilities:

```text
Business Outcome Owner
Capability Owner
System Owner
AI / Automation Owner
Data / Knowledge Owner
Security / Risk Owner
Evaluation Owner
Operations Owner
```

---

## 4. Governance cadence

Possible cadences:

```text
continuous controls
weekly operational review
monthly capability review
quarterly architecture review
event-driven incident review
```

---

## 5. Governance forum

A formal committee is optional.

What matters is that material decisions have:

```text
owner
evidence
decision record
review trigger
```

Decisions are recorded as `DEC-###` (`artifacts/decision-assumption-log.md`); human gates: `STANDARD.md` §8.

---

## 6. Governance review triggers

Review SHOULD occur when:

```text
an autonomy increase is proposed
model/provider changes materially
data access expands
new tool permissions are added
risk classification changes
business policy changes
failure patterns emerge
economics drift
```
